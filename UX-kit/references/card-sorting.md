# 卡片分类 (Card Sorting)

本文档整合了卡片分类的研究方案设计参考（样本量、模式选择、实施流程）与嵌入访谈时的任务模块设计（话术模板、追问要点、输出格式），供 UX-kit 的方案设计与访谈提纲生成共用。

---

## 一、适用场景
- 设计或优化信息架构（IA）
- 确定导航菜单结构和层级
- 内容分类和标签命名
- 理解用户对信息/功能分组的心理模型
- 网站/App 改版前的信息组织验证
- 验证现有分类是否符合用户心智模型

**信号关键词**：信息架构、导航、分类、菜单、信息组织、内容结构、归类、标签

---

## 二、执行模式选择
卡片分类在方法本质上是独立的数据收集方法——有自己的研究问题（用户如何理解信息分组）、样本量标准（15-30人）和分析方法（聚类分析、树状图）。但在实践中几乎总是配合访谈使用，因为需要"出声思考"来获取用户的分组逻辑。因此本方法在研究方案中有两种执行模式：

### 2.1 模式一：嵌入用户访谈（默认）
卡片分类任务嵌入在访谈后半段（15-20分钟），使用同一批被访者。适用条件：

- 样本量在访谈范围内（8-12人），且研究目标以定性洞察为主
- 面对面执行，研究员可观察和追问分组逻辑
- 分析以定性为主（关注分组模式和命名逻辑），不要求统计显著性

此模式下，样本量按主采集方式（用户访谈）的要求计算。

### 2.2 模式二：独立数据采集阶段
卡片分类作为一个独立的研究阶段执行，独立招募用户、独立时间窗口。触发条件：

| 条件 | 说明 |
|------|------|
| 样本量需求超出访谈范围 | 需要聚类分析或树状图稳定性时，至少需要 **15 人以上**（访谈通常仅 8-12 人） |
| 采用在线无主持工具 | 通过 OptimalSort、UXtweak 等工具在线执行，不涉及同步访谈 |
| 研究目标是验证而非探索 | 验证已有信息架构是否合理，需要定量证据（封闭式卡片分类为主） |

此模式下：
- 样本量使用卡片分类自身标准（参考第三节推荐样本量表）
- 阶段数计入研究方案的 ≤4 阶段限制
- 如需配合出声思考，可额外安排 3-5 人的简短补充访谈

### 2.3 模式选择判定
```
卡片分类需求
├─ 样本量 ≤ 12 人 + 面对面执行 + 分析以定性为主 → 模式一：嵌入访谈
├─ 样本量 ≥ 15 人 + 需要统计验证 → 模式二：独立阶段
├─ 在线无主持工具 + 无需同步访谈 → 模式二：独立阶段
└─ 不确定 → 默认模式一，方案中标注样本量不足时的注意事项
```

## 三、推荐样本量
**基本规则**：样本量一般 **15 人左右**。

**按卡片数量调整**：

| 卡片数量 | 推荐样本量 | 说明 |
|---------|-----------|------|
| < 30 张 | 6-10 人 | 分类任务简单，较少人即可观察到分组模式 |
| 30-60 张 | 15 人左右 | 标准情况 |
| > 60 张 | 20-30 人 | 卡片量大，需更多人以覆盖不同分组方式 |

**补充参考**：

| 调整因素 | 对样本量的影响 |
|---------|-------------|
| 在线工具执行 | 可增加 5-10 人（在线成本低） |
| 领域专家难招募 | 可降至 10-15 人 |
| 需要聚类分析（树状图）统计稳定 | 至少 15 人 |
| 开放式探索 | 20-30 人（覆盖更多分组模式） |
| 封闭式验证 | 12-15 人（验证一致性） |

## 四、样本特征与配额
### 4.1 核心筛选维度
- **目标用户代表性**：是产品的实际或潜在使用者
- **领域熟悉度**：对卡片内容涉及的领域有基本认知
- **排除条件**：UX 设计师、信息架构师、产品经理（专业偏见）
- 被访者能理解卡片内容的基本含义
- 被访者代表的是"用户如何使用信息"而非"专家如何组织信息"

### 4.2 配额设计原则
| 配额维度 | 分层建议 | 目的 |
|---------|---------|------|
| 产品经验 | 新手:中级:资深 ≈ 1:1:1 | 不同经验用户对分类有不同心智模型 |
| 主要使用目标 | 按任务类型分层 | 不同任务需要不同的信息路径 |
| 角色/职能 | B 端按与信息架构相关的职能分层 | 不同角色关注不同信息 |

配额维度 1-2 个，重在多样性而非统计精确配比。

## 五、实施要点
### 5.1 核心流程
1. **卡片准备**：列出需要分类的所有内容/功能/页面（建议 30-60 张卡片）
2. **选择执行方式**：
   - 面对面：实物卡片，每次 1 人，30-60 分钟，可观察用户思考过程
   - 在线：使用 OptimalSort、UXtweak 等工具，可远程规模化
3. **执行分类**：开放式让用户自由分组并命名，封闭式给用户预设分类
4. **数据分析**：
   - 构建相似度矩阵
   - 层次聚类分析生成树状图（Dendrogram）
   - 分析各层级分组的一致性和分歧
5. **结果应用**：将分析结果转化为导航结构方案

### 5.2 卡片准备原则
- 每张卡片简短清晰（2-4 个字），用用户语言而非产品术语
- 避免专业术语和缩写
- 既有功能名称也有内容类型
- 卡片数量 30-60 张（少于 20 张无分类意义，超过 80 张用户疲劳）

### 5.3 关键原则
- 开放式分类中不要预先暗示任何分类
- 允许用户创建"不清楚/不合适"堆
- 记录用户的出声思考（Think Aloud），理解分组逻辑
- 关注分类标签的用语：用户用的词 vs 产品用的词（差距揭示心智模型差异）

### 5.4 物料准备（面对面方式）
- 实物卡片（打印/手工制作）
- 记录表（记录分组结果和用户思考）
- 录音/录像设备
- 礼金 200-400 元/人

### 5.5 工具推荐（在线方式）
- OptimalSort、UXtweak、UserZoom、kardSort
- 线上远程访谈白板：Miro / FigJam

## 六、嵌入访谈的任务模块设计
当采用模式一（嵌入用户访谈）时，按以下方式设计访谈提纲中的卡片分类模块。

### 6.1 在访谈提纲中的位置
```
核心访谈模块（40-50分钟）
    ↓
卡片分类任务（15-20分钟）
    ↓
收尾（5分钟）
```

### 6.2 任务模块结构
| 环节 | 时长 | 内容 |
|------|------|------|
| 任务说明 | 2分钟 | 解释规则：按自己的理解分组，没有对错 |
| 开放式分类 | 10分钟 | 用户自由分组并给每组命名 |
| 出声思考 | 伴随 | 记录分组逻辑和疑惑点 |
| 结果确认 | 3分钟 | 复述用户分组，确认理解 |

### 6.3 任务说明话术模板
> "接下来我们做一个小的分类任务。这里有 N 张卡片，每张上写着一个功能/内容。请你按照你自己的理解，把这些卡片分成几组。你觉得哪些应该在一起就放在一起，然后给每组起一个名字。没有对错之分，完全按你的想法来。"

### 6.4 追问要点
- 用户分组时追问："为什么这个放在这组？"
- 用户犹豫时："这两组之间的区别是什么？"
- 命名时："为什么叫这个名字？还有没有其他更贴切的叫法？"
- 全局："有没有哪些卡片你觉得放哪都不合适？"

### 6.5 提纲中的输出格式
```
### 模块X：卡片分类任务（约15分钟，嵌入技术）

**任务目标**：了解用户对[内容领域]的心智分组模型

**物料准备**：
- 卡片 N 张（内容列表见附表）
- 记录表（分组结果 + 出声思考记录）

**流程**：
1. 任务说明（2分钟）：[话术]
2. 开放式分类（10分钟）：引导用户出声思考
3. 结果确认（3分钟）：复述分组 → 追问争议卡片 → 确认命名
```

## 七、常见误区
- 卡片数量过多（>80 张），用户疲劳导致后段分类随意
- 卡片描述使用内部术语而非用户语言
- 样本量太少（<10 人），树状图结构不稳定
- 只做封闭式不做开放式，限制了发现用户心理模型的机会
- 将卡片分类结果直接等同最终导航设计（还需考虑业务需求和技术约束）

---

## 八、与其他方法的衔接
- **← 用户访谈**：访谈中提到的"找不到"的信息作为卡片分类的重点验证对象
- **→ 可用性评估**：卡片分类形成的导航结构在可用性测试中验证
- **← 问卷调查**：问卷中关于信息查找困难的反馈作为卡片分类的设计输入
