# UX 研究工具箱 (UX-kit)

## 设计目标

用户用一句话提出研究诉求，UX-kit 自动判断产出内容：**明确要问卷就直接产出问卷，明确要访谈提纲就直接产出提纲，明确要可用性测试方案就直接产出测试方案**；诉求模糊或涉及多种材料时，先产出研究方案供用户确认，确认后再按阶段产出对应的研究材料（问卷 / 访谈提纲 / 可用性测试方案，每份一个文件）。所有产出前都经过"研究问题陈述 → 用户确认"环节，确保方向正确；生成时直接复用各材料的完整生成规则，不重复设计。

## 整体流程

```
用户一句话
    ↓
Phase 0: 输出模式识别（问卷 / 提纲 / 可用性 / 方案）
    ↓
Phase 1: 问题澄清（按模式差异化追问 → 研究问题陈述 → 用户确认）
    ↓
Phase 2: 按模式产出
  ├─ 2A 问卷模式   → 完整问卷（需求分析与模式识别 → 结构 → 题项）
  ├─ 2B 提纲模式   → 完整访谈提纲（话题模块 → 四列表格 → 附录）
  ├─ 2C 可用性模式 → 完整可用性测试方案（目标 → 任务卡 → 回顾/结束语）
  └─ 2D 方案模式   → 研究方案 → 用户确认 → 按阶段生成材料（每份一文件）
    ↓
输出：Markdown 文档，按模式命名保存至 outputs/
```

## Phase 0: 输出模式识别

### 模式判定

从用户输入中识别产物意图，判定产出模式：

| 输入信号 | 模式 |
|---------|------|
| 含"问卷/调查表/量表/问卷编制/满意度问卷"等 | **问卷模式** |
| 含"访谈/访谈提纲/访谈大纲/深度访谈"等 | **提纲模式** |
| 含"可用性测试/可用性评估/易用性测试/测试方案"等 | **可用性模式** |
| 含"研究方案/调研方案/用户研究/研究/调研"或**无明确产物词** | **方案模式**（默认） |
| 同时含多种产物词（如"问卷和访谈都做"） | **方案模式** |

### 模式切换

- 澄清过程中用户修正产物意图（"其实我只要问卷"）→ 切换到对应模式，按新模式重新澄清
- 判定困难时默认方案模式——它是安全兜底：方案确认前用户有纠正机会，确认后材料产出前又可再调整

## Phase 1: 问题澄清

把用户模糊的一句话变成一句清晰的研究问题。允许多轮交互，但**不做固定剧本**——输入已足够清晰时少问或不问。

### 触发条件

用户输入存在以下任一特征时主动澄清：

| 信号 | 示例 |
|------|------|
| 研究目标过于宽泛 | "用户还有什么需求" |
| 核心概念模糊未定义 | "体验怎么样" |
| 多个问题混在一起 | "满意度和使用习惯和新功能接受度" |
| 只给了动作没有方向 | "帮我调研一下这个产品" |

**不触发**：用户输入已包含清晰的研究对象 + 目标人群 + 研究意图，直接进入产出流程。

### 交互方式

每轮使用 `question` 工具与用户交互，设置 `multiple: true` 和 `custom: true`。每个选项使用 `☐` 前缀，选项末尾始终包含"跳过此问题"和"其他（请描述）"兜底项。选项的具体措辞参考 `references/question-templates.md`（按研究类型分类的选项模板 + 产品阶段对照表），模板未覆盖的场景根据用户原话自由设计。

### 澄清维度（按模式差异化）

| 维度 | 方案模式 | 问卷模式 | 提纲模式 | 可用性模式 |
|------|---------|---------|---------|-----------|
| 研究方向 | 模糊时必问 | 必问（调研主题） | 必问（访谈目标） | 必问（测试目标） |
| 研究动机/决策背景 | 决策场景必问 | 可省 | 可省 | 可省 |
| 目标人群 | 必问 | 必问 | 必问 | 必问（目标用户） |
| 聚焦范围 | 可聚焦时问 | 可省 | 可省 | 必问（评估对象/功能范围） |
| 约束条件 | 有压力才问 | 有压力才问 | 时长/线上必问 | 原型/时长必问 |
| 设计模式/模型 | 自动匹配 | 自动判断（见 2A） | 不适用 | 不适用 |
| 产品/话题背景 | 方案层推断 | 可省 | 必问 | 必问（待体验的功能） |

> 设计模式/模型（Kano/ETS/量表）与嵌入技术（JTBD/卡片分类等）一律**自动判断**，不追问用户；用户主动指定了模型或方法时尊重用户指定。

### 追问策略

1. 回顾用户已有输入，标记缺口
2. 从缺口中挑**最重要的一个**发问（`question` 工具，多选 + 自定义），一次只问一个核心维度
3. 用户回答后，先做一句话总结确认，再更新缺口清单
4. 重复，直到剩余缺口不影响产出。大多数情况 3-5 轮收工

**主动追下去**：回答仍比较泛（"体验不好"→ 哪个环节？谁的体验？什么场景下）；跳过了影响产出的维度；明显必要但未提及的维度。

**可以少问**：初始输入已覆盖大部分维度；用户"你帮我定"；剩余缺口产出层可自行处理。

**停止条件**：关键信息已明确；用户明确不再细化；再问边际收益低。

### 输出：研究问题陈述（必须确认）

澄清完成后输出研究问题陈述并请用户确认：

```
## 研究问题陈述

[一句自然语言概括：研究对象 + 目标人群 + 研究意图（含研究类型/模式）]

---

以上理解是否正确？确认后我将开始生成。
```

**必须等待用户明确确认后才能进入 Phase 2**，确认前不得继续生成。若用户提出修改意见，按修改更新研究问题陈述后再请用户确认。若多轮后仍不清晰，输出当前最接近的解读并标注"存在不确定性"。

## Phase 2: 按模式产出

### 2A 问卷模式 → 完整问卷

按"需求分析与模式识别 → 问卷结构设计 → 题项编写"生成完整问卷，按 `templates/questionnaire.md` 填充。

#### Step A: 需求分析与模式识别

**A1 识别设计模式**：

| 设计模式 | 判定条件 | 设计路径 |
|---------|---------|---------|
| **量表驱动型** | 已有维度/指标框架，需量化测量 | 维度→指标→题目，输出测量框架表 |
| **开放探索型** | 目的是发现痛点、收集建议，不预设维度 | 按信息需求分模块，开放题为主 |
| **方法论驱动型** | 指定了具体方法论（Kano、ETS 等） | 严格遵循方法论规则设计对应模块 |
| **混合型** | 以上多种模式组合 | 分区设计，各走各的路径 |

**A2 模型判断（方法论驱动型专用）**：

| 信号关键词 | 模型 | 说明 |
|---|---|------|
| "功能优先级""需求分类""功能排序""Kano" | **Kano** | 每个功能点需正反双题 |
| "满意度""满意程度""功能满意度""体验评估""体验诊断""ETS""整体体验水平""体验度量" | **ETS** | 进一步区分 ETS-U / ETS-E；待测对象与 8 维度不完全匹配时按最小改动原则适配题项表述（见 Step C） |
| "认知调研""行为调研""通用调研" | **通用** | 按量表驱动或开放探索设计 |
| 多目标混合 | **混合** | 组合多个模型/模式模块 |

**A3 ETS 子模式选择（当判定为 ETS 时）**：

| 条件 | 选择 | 说明 |
|------|------|------|
| 面向终端用户大规模发放 | **ETS-U** | 1 道 NPS + 2 道多选题，2-3 分钟 |
| 专家/内部团队精细评估 | **ETS-E** | 48 条满意度 + 26 条重要度，15-20 分钟 |
| 需要兼顾 | **同时输出两套** | 分别提供 ETS-U 和 ETS-E 问卷 |

**A4 读取参考文件**：Kano → `references/kano-model.md`；ETS → `references/ets-model.md`；通用/量表/开放 → `references/question-design.md`。

#### Step B: 问卷结构设计

按模板骨架组织：设计说明（研究背景与目的 / 设计模式 / 测量框架表 / 方法论模块说明）→ 指导语（研究目的、保密承诺、匿名说明、预计时长、感谢语）→ 甄别题 → 主体问卷 → 结语。

- **甄别题**：筛选目标被访者，跳转逻辑在题目旁 inline 标注（`否 [跳转：选此项跳至结语]`）
- **人口统计学**：作为主体问卷中的一个模块，用作分组筛选时放最前（甄别题之后）、仅事后分类时放最后，标题统一用"基本信息"
- **测量框架表**（量表驱动型）：输出「维度→指标→操作化定义→对应题目」映射表；每个量表类指标至少 2 题，每维度 3-5 题
- **逻辑控制**：跳转/展示逻辑一律 inline 标注在题目/选项旁（`[展示逻辑：仅当 Q3 选了"功能异常"时显示]`），复杂时附录一汇总总览表

#### Step C: 题项编写

题目的五条表述规范（一题一问、具体可感知、中性表述、避免否定嵌套、不预设前提）与选项设计四项原则（互斥、穷尽、平衡、特异），以 `references/question-design.md` 的完整正反例表为准，生成时逐题对照检查。

**按模型选择题型**（嵌入技术的完整规则以对应参考文件为准）：
- 通用问卷：题型库见 `references/question-design.md`；开放题 ≤ 3 题，提供思考锚点，避免引导性
- Kano：每个功能点正向+反向双题，五级选项，放主体问卷开头（甄别题之后），详见 `references/kano-model.md`
- ETS-U：1 道 NPS (0-10) + 2 道多选题（8 选项映射 8 维度），2-3 分钟；ETS-E：48 条满意度陈述 + 26 个重要度指标，15-20 分钟，详见 `references/ets-model.md`
- 可附加使用行为题、开放题等模块与 ETS 核心题自然衔接

**ETS 题项表述适配规则**：待测对象与 ETS 8 维度内容不完全匹配时（如"首页满意度"这类局部功能评估），按**最小改动原则**适配——能不改就不改（仅替换产品/对象名称等必要填充）；必须改时改动幅度尽量小，且改写后的题项保持与原题项想测的**指标含义接近**（语义保真，如"智能助手指令识别"改为"首页个性化推荐符合需求"时测的仍是智能化维度的推荐准确性含义）。**不可动**：NPS 0-10 分制、8 选项映射 8 维度结构、ETS-E 48 条陈述 + 26 重要度指标的条数与三层映射结构、计分方法与四级十二档。维度删减仅限 `references/ets-model.md`"维度适用性说明"的两个场景（内部员工系统删运营服务 / 纯技术平台删视觉交互）。

**兜底场景**：待测对象为**线下服务类**（如食堂、网点服务），ETS 8 维度框架基本不适用时，允许自建维度量表，但**必须在问卷设计说明中注明理由**（如"ETS 维度体系面向标准消费者产品，线下服务场景不适用，采用自建维度量表"）。

#### Step D: 附录

- **数据分析计划**：ETS 问卷只写 ETS 得分计算和体验优化矩阵；其他问卷按分析目的列出方法、涉及题目和预期产出
- **质量控制建议**：预测试 3-5 人认知访谈、无效问卷标准（作答时间过短、规律性作答）、信效度要求（Cronbach's α ≥ 0.7，量表驱动型）

### 2B 提纲模式 → 完整访谈提纲

按"确定话题模块 → 识别嵌入技术 → 四列表格 → 概述与附录"生成完整提纲，按 `templates/interview-guide.md` 填充。

#### Step A: 确定话题模块

1. 研究问题陈述中已给出话题结构的，以其为准
2. 否则根据研究目标自行拆解 3-5 个核心话题，顺序：简单→复杂、具体→抽象
3. 每个话题模块约 10-20 分钟；开场暖场（自我介绍、录音同意）和收尾（查缺补漏、感谢）也是独立模块

#### Step B: 识别嵌入技术的影响

| 嵌入技术 | 匹配信号 | 对提纲的影响 |
|---------|---------|-------------|
| JTBD | 涉及用户选择/切换/决策 | 该模块题目按决策链展开（触发→竞争→决策→评估），参考 `references/jtbd-framework.md` |
| 灵犀旅程 | 涉及端到端体验/旅程 | 该模块按旅程五要素展开（场景→行为→触点、驱动因素、体验指标、典型问题、优化点），参考 `references/journey-mapping.md` |
| 卡片分类 | 涉及信息架构/导航分类 | 在所有话题模块后加入卡片分类任务（约15分钟），任务设计参考 `references/card-sorting.md` |

#### Step C: 提纲主体：分级结构 + 四列表格

每个话题模块是一个章节标题，标题下用斜体写核心目标（一句话），然后是四列表格：

```
### 一、[话题名称]（约X分钟）
*[该环节的核心目标，一句话]*

| 维度 | 核心问题 | 追问 | 执行要点 |
|------|---------|------|---------|
| [维度A] | [问题1] | [追问链] | [操作提示] |
| | [问题2] | [追问链] | [操作提示] |
```

- **维度列**：一个模块 2-3 个维度，每维度 1-3 题，同一维度多题合并单元格
- **核心问题列**：锚定具体事件（"上一次你办卡是什么时候？"而非"你平时怎么办卡？"）、开放不引导、一次只问一个问题、先问事实再问感受再问看法（内部用 CBA 原则组织，参考 `references/cba-framework.md`，**不在提纲中输出方法标签**）
- **追问列**：预判回答方向给出追问路径，用 `→` 表示递进
- **执行要点列**：访谈员现场的操作指引，写白话不写术语——防卡壳、语气提醒、换角度、避免陷阱、特殊用户应对、投射技巧；探询技术翻译为白话时参考 `references/probing-techniques.md`

**执行要点写法原则**：给具体可操作的白话指令（"如果用户说 XX，可以试试问 YY""这里注意语气放轻松，像朋友聊天"），不解释题目设置目的、不写专业术语（"采用 360 度提问法"❌）。

#### Step D: 概述与附录

提纲开头写概述：**预计时长**、**提纲设计思路**（陈述大环节用到的方法与设计逻辑，如"整体按情景→行为→态度的递进组织题目""涉及决策的'XX选择'环节采用 JTBD 决策链逻辑"）。**研究背景与目标、被访者画像已由澄清/方案部分覆盖，不要在提纲概述中重复**。提纲末尾附**使用说明**：访谈前准备（环境、物料、文档）、执行注意事项（时间把控、录音检查、访谈礼仪、记录要点、结束动作）。

### 2C 可用性模式 → 完整可用性测试方案

按 `templates/usability-test.md` 生成完整测试方案（测试目标 → 开场白 → 测试前调研 → 测试任务 → 总结回顾 → 结束语 → 附录记录表），方法规则与任务卡设计详见 `references/usability-test-guide.md`。

**测试目标**：勾选式列出，与任务及探寻内容有明确对应。

**任务卡设计**（每个任务一张卡：场景 / 任务步骤 / 探寻问题 / 完成标准 / 参与者打分）：
- 评估清单重点关注**高频、新增、有疑问**的功能
- 任务以**用户视角**编写，避免技术化语言；任务范围聚焦，避免过宽
- 评估材料尽量基于**高保真动态原型**
- 完成标准三分法：✓ 成功（无帮助）/ ○ 成功有困难（1-2 次提示）/ ○ 失败（2 次以上帮助）
- 探寻问题覆盖四类：理解度、操作效率、方案对比、预期差异

**开场白与结束语**：使用模板标准话术，开场白**必须包含"评估的是产品不是用户能力"声明**。

**执行要点**：引导出声思维，重点观察完成任务全流程的行为，可按需记录任务完成率、操作时间等定量数据。

**附录**：任务记录表（耗时 / 提示次数 / 是否成功 / 参与者打分）。

### 2D 方案模式 → 研究方案 → 确认 → 材料

#### Step A: 需求解析

1. **研究类型**：探索型（理解行为、发现需求、定义问题空间）/ 测量型（量化现状、确定优先级、验证假设）/ 评估型（测试方案、诊断问题、比较方案）/ 描述型（刻画群体、建立认知基线）
2. **研究子目标拆解**：一句话需求拆解为具体子目标（如"了解认知 + 挖掘需求 + 验证普遍性"）
3. **约束条件**：时间紧迫程度、可及样本规模、有无实验室设备

#### Step B: 层级式方法匹配

**先选数据采集方式 → 再选嵌入技术 → 合并同类阶段。**

**主采集方式匹配（按研究类型）**：

| 研究类型 | 主采集方式 | 判断依据 |
|---------|-----------|---------|
| 探索型 | **用户访谈** | 需要深入理解原因、动机、态度，定性数据 |
| 测量型 | **问卷调查** | 需要量化、统计、验证普遍性，定量数据 |
| 评估型（体验水平） | **问卷调查** | ETS体验评估需要大规模用户评分 |
| 评估型（交互界面） | **可用性评估** | 需要观察操作行为、任务绩效 |
| 描述型 | **用户访谈 + 问卷调查** | 先定性探索维度，再定量描述分布 |
| 已有数据利用 | **用户声音分析** | 需要从现有反馈文本中提取洞察 |

**嵌入技术匹配（按研究子目标）**：

| 子目标/信号关键词 | 嵌入技术 | 依附的主采集方式 |
|------------------|---------|----------------|
| 功能优先级、需求分类、先做什么 | **卡诺模型** | 问卷调查（正反双题模块） |
| 满意度评估、体验诊断、整体体验水平、ETS | **ETS体验评估** | 问卷调查（ETS-U / ETS-E 模块） |
| 用户选择、切换决策、购买动机、竞品对比 | **JTBD** | 用户访谈（决策链模块） |
| 信息架构、导航分类、内容归类 | **卡片分类** | 用户访谈（后半段任务，默认）/ 独立阶段 |
| 视觉注意、页面布局、视线 | **眼动测试** | 可用性评估（同步采集） |
| 体验旅程、触点、流程 | **灵犀旅程** | 用户访谈（旅程回溯模块） |
| 用户角色、群体特征、行为画像 | **用户画像** | 访谈+问卷合成综合产出 |

**合并同类阶段**：同一主采集方式承载多个嵌入技术时合并为一个阶段（如"卡诺模块+ETS模块"合入同一问卷阶段）；阶段数 ≤ 4（按数据采集方式计数）；卡片分类样本量需求超出访谈范围（≥15 人）或采用在线无主持工具时，可作为独立阶段（样本量用卡片分类自身标准 15-30 人）。

**读取参考文件**：四种采集方式 → `references/research-methods.md`；卡诺 → `references/kano-model.md`；ETS → `references/ets-model.md`；卡片分类 → `references/card-sorting.md`；灵犀旅程 → `references/journey-mapping.md`；眼动 → `references/eye-tracking.md`；画像 → `references/persona.md`；样本量精确计算（用户提供置信参数时）→ `references/sample-size-calculator.md`。

#### Step C: 产出研究方案（纯方案）

按 `templates/research-plan.md` 生成**纯方案文档**（不含完整材料，材料位置写内容概述）→ **必须等待用户确认方案**。

文档六部分与要点：

- **一、研究背景与目标**：研究背景（为什么做）→ 研究目标（编号列表）→ 核心研究问题（一句话，放本部分最后）
- **二、研究设计总览**：用**箭头流程图**展示阶段序贯——阶段框内只用**简短方法名**（如"深度访谈""问卷验证"），研究性质只标注**定性/定量**两类（按该阶段主要数据形态判断）；箭头标注阶段产出。流程图下方附**设计说明**，共三层：
  - 每阶段回答什么问题：用简洁短语自拟（参考"是什么、为什么"vs"有多少、有多重要"的精神，按场景写自己的表述，如"哪些地方不满意、为什么不满意"）
  - 方法选择理由：为什么选这个方法（一句话）
  - 阶段衔接：前序阶段产出如何作为后序阶段输入
  - 单阶段只画一个阶段框；含综合产出（画像/旅程图）时在末端追加
- **三、目标用户定义与样本设计**：目标用户定义（人群/细分/排除）+ 各阶段样本设计合并为一张表（阶段/样本量/特征要求/配额）；样本量按主采集方式经验值，嵌入技术不额外增加，配额维度 ≤ 3
- **四、具体研究阶段**：每阶段只含三块：
  - 阶段标题体现**核心目标+方法**（如"探索用户需求与痛点（用户访谈，含 JTBD）"）
  - **目标**：一句话，简洁明了
  - **材料小节标题直接用材料名**（访谈提纲 / 问卷 / 可用性测试方案 / 声音分析计划），内容写内容概述——"确认后生成《[主题]访谈提纲.md》，包括 [话题模块概览]"；声音分析计划无独立文件，概览直接内嵌
  - **预期产出**：成果物列表
  - 不写样本设计与实施要点（样本在第三部分，实施安排见第五部分）
- **五、实施流程及时间计划**：以**阶段 × 事项**为维度排表（表头：阶段/事项/预估时间（天）），每阶段拆 3-4 个事项（招募与排期、执行、数据整理与分析、产出交付），时间为各事项预估天数；末尾给出**预计总耗时**——按串行累加总天数，如有可并行事项（如问卷投放与访谈执行重叠）注明实际日历周期可压缩
- **六、注意事项**：局限性与风险提示

**多阶段组合规则**：定性在前（探索）、定量在后（验证/测量）；同一数据采集方式的嵌入技术合并到同一阶段；明确前序阶段产出如何作为后序阶段输入；不同阶段招募不同用户；阶段数 ≤ 4。

**方案确认**：用户确认方案后进入 Step D；若用户提出修改，按修改更新方案后再确认。

#### Step D: 生成研究材料（确认后）

用户确认方案后，按阶段生成材料，**每份材料一个文件**：

| 阶段采集方式 | 生成文件 | 生成规则 |
|------------|---------|---------|
| 用户访谈 | `outputs/[主题]访谈提纲.md` | 2B 提纲规则全流程 |
| 问卷调查 | `outputs/[主题]问卷.md` | 2A 问卷规则全流程（A2 模型判断与方案方法匹配结果一致，直接沿用；A1 设计模式仍需独立判定） |
| 可用性评估 | `outputs/[主题]可用性测试方案.md` | 2C 可用性规则全流程 |
| 用户声音分析 | 内嵌方案文档 | 声音分析计划（数据来源与渠道清单、时间跨度与采样策略、清洗规则、分析方法、输出形式） |

材料生成后执行对应质量检查清单，并告知用户全部文件路径。

## 质量检查

按产出模式执行对应清单：

**方案清单（2D）**
- [ ] 每个阶段是否以数据采集方式为锚点？嵌入技术是否正确归入？
- [ ] 是否有可合并的阶段被拆开？阶段总数是否 ≤ 4？
- [ ] 六部分结构是否齐全（背景与目标/设计总览/用户与样本/具体阶段/时间计划/注意事项）？
- [ ] 设计总览是否为箭头流程图？阶段框内是否用简短方法名 + 定性/定量标注（无冗长阶段名）？
- [ ] 设计说明是否含三层：各阶段回答什么问题（简洁自拟）、方法选择理由、阶段衔接？
- [ ] 各阶段样本设计是否合并在第三部分一张表（阶段/样本量/特征/配额）？样本量按主采集方式计算？配额维度 ≤ 3？
- [ ] 阶段标题是否体现核心目标+方法？"目标"是否一句话简洁？
- [ ] 材料小节标题是否为材料名（访谈提纲/问卷/可用性测试方案/声音分析计划），内容是否为"确认后生成《××.md》，包括××模块"式内容概述？
- [ ] 实施流程及时间计划是否为阶段×事项表（含预估天数）？是否给出预计总耗时（含可并行说明）？
- [ ] 是否未在阶段内重复样本设计与实施要点？

**问卷清单（2A / 2D 问卷阶段）**
- [ ] 设计模式与模型判定是否正确（量表驱动/开放探索/方法论驱动/混合；Kano/ETS/通用）？
- [ ] 是否存在双重问题、引导性措辞、否定嵌套、假设性前提？
- [ ] 题目是否可追溯到研究目标？选项是否互斥且穷尽？多选是否标注"（可多选）"？
- [ ] Kano 正反题是否配对完整？ETS-U 的 NPS 是否为 0-10 分制？ETS-E 陈述 48 条、重要度 26 项（条数保留）？题项适配是否遵循最小改动原则（语义保真）？线下服务类自建量表是否在设计中注明理由？
- [ ] 量表驱动型是否输出了测量框架表？

**提纲清单（2B / 2D 访谈阶段）**
- [ ] 每个话题模块是否有标题 + 斜体目标 + 四列表格？
- [ ] 题目是否开放、锚定具体事件？执行要点是否白话可操作？
- [ ] 是否覆盖所有研究目标？是否含开场暖场与收尾？
- [ ] 是否存在禁忌题目（否定假设、未来预测、让用户定价/设计、双重问题）？
- [ ] 概述中是否未重复研究背景与目标/被访者画像？

**可用性清单（2C / 2D 可用性阶段）**
- [ ] 测试目标是否与任务、探寻内容有明确对应？
- [ ] 任务卡是否完整（场景/任务步骤/探寻问题/完成标准/参与者打分）？
- [ ] 任务是否以用户视角编写、避免技术语言？是否聚焦高频/新增/有疑问功能？
- [ ] 开场白是否含"评估产品而非用户能力"声明？是否含总结回顾与结束语？
- [ ] 附录是否含任务记录表？

## 全局策略

### 多角色处理

- **默认**：一套材料，通过基本信息区分角色
- **角色差异大**：访谈提纲核心题目不变、"执行要点"按角色微调；问卷拆分为多套、核心量表保持一致

### 特殊场景处理

| 场景 | 处理方式 |
|------|---------|
| 资源极度有限（1-2 天） | 轻量方法：5 人快速访谈 + 嵌入卡片分类、在线问卷 |
| 涉及多个用户群体 | 按群体分别设计样本特征和配额，访谈覆盖各类群体 |
| B 端产品研究 | 样本量适当下调，注重决策链角色覆盖，涉及决策的话题用 JTBD 逻辑组织 |
| 访谈时长受限（≤30 分钟） | 聚焦 1-2 个核心话题，每话题精简到 2-3 题 |
| 新手被访者 | 暖场时间加长，题目更具体场景化 |
| 线上访谈 | "执行要点"中多给防冷场提示（缺少非语言线索） |
| 有前置数据/访谈发现 | 背景中引用；问卷优先从访谈发现提取维度并标注"来源：访谈"；访谈暖场融入"从之前的问卷里我们看到……你觉得呢？" |
| 需求超出支持方法范围 | 说明支持的方法清单，给出替代建议 |

### 常见错误提醒

- 不要套用同一结构——先做模式识别与方法匹配，再差异化设计
- 方案模式：材料小节写"确认后生成《××.md》，包括××模块"式内容概述即可，不要把材料全文抄进方案；样本设计只写在第三部分，不要在阶段内重复
- 问卷模式：模型判断（Kano/ETS/通用）自动完成，不问用户；用户指定时尊重指定
- Kano 正反题必须配对；ETS-U 的 NPS 是 0-10 分制；ETS-E 的 48 条陈述与 26 重要度指标条数保留，表述按最小改动原则适配（语义保真）；线下服务类自建量表须在问卷设计说明中注明理由
- 访谈提纲不要出现 CBA/JTBD/ORID 等专业术语——那是内部工具，不是给访谈员看的；"执行要点"给操作指引，不给意图解释
- 访谈问题是探针不是选择题；问卷题目不是访谈探针，两者写法不可互换
- 澄清输出研究问题陈述后必须等用户确认，确认前不得继续
